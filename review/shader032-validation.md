# 0.3.2 perspective shader repair

The addon ports the shader-only correction from [IsoRim 3a5697e](https://github.com/peren717/IsoRim-1.7/commit/3a5697e5f7e482bb04a9b7594263a174bea92070). `ToEye(p)` converts the drawn eye height to the same true-space coordinates as the fragment. Perspective face-normal orientation and rim lighting use this direction; orthographic uses the original `_IsoView.xyz`. Normal-map tangent basis, uniforms, vertex layout, clipping, floor fade, LOD policy and exact host-DLL compatibility gate are unchanged. Upstream MIT notices remain in place.

The host remains the already accepted API61 DLL, SHA256 `3A22565D697E78A5D15210C7B861F0FEBFD80C62C8D9D409D6529E2F990B1861`. The upstream fix commit changes only `Shaders/IsoRimSolid.frag.glsl`; no host DLL or new API is required to apply the correction to our shader. The addon version log and metadata become 0.3.2. This corrects the addon's shader, not any independently maintained native host shader.

Validation uses installed RimWorld **1.7.5000 rev1275**, isolated save-data folders and the real API61 host. C# build succeeds, and the game renders the custom GLSL material with a normal texture and complete normal/tangent streams.

- `shader-run032-02`: eight phases: orthographic 45°, perspective 45°/90°/270°, free yaw 91.5°, rim light at 90°, actual pawn first person, return to orthographic. Assertions confirm projection mode, first-person state, shader/material presence, texture binding and geometry streams. Logs record actual yaw/FOV/squash. Raw screenshots were visually inspected: no broad speckled face patches were observed, baked details remained visible, and rim light changed the expected edges. Fine edge aliasing is not claimed to be eliminated.
- `floor-run032-01`: the existing 21-phase three-floor regression checks 258 upper buildings, near/mid/far transitions, lower-floor policy, hidden-floor work avoidance, peek fade, perspective offsets, rotation, night lighting, fog/roof/slab coverage, save/reload and hidden despawn. Peek/perspective images were reviewed; the deliberate floor-fade dither remains expected.
- `shader-run032-01` was stopped after finding an incorrect yaw offset in the test fixture. Its protected-file check passed. It is not acceptance evidence; the corrected second run logs actual camera yaw.

Final completion, protection and package hashes are in [shader032-provenance.json](shader032-provenance.json). Public assertion logs and selected unedited screenshots are under [shader032/](shader032/). Full raw captures stay in the isolated validation directories. Missing unrelated Workshop subscriptions can emit ambient errors; no claim is made that the entire game log is error-free. This is scoped visual/runtime regression, not an old/new pixel-difference benchmark, whole-game performance result, dynamic-asset validation or full-mod-stack acceptance.
